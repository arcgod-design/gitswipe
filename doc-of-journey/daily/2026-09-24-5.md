# 2026-09-24 (session 5) — WEEK-04: opportunity engine (deterministic core)

## What was built

- `packages/discovery/src/dedup.ts` — exact duplicate (normalized-title identity) + lexical similarity (token Jaccard, stopword-stripped) + metadata corroboration (same repo / shared labels) → exact_duplicate | likely_duplicate | related | novel_candidate. Never one signal alone (contract §11); embeddings slot in later behind the same classifier.
- `packages/discovery/src/finding.ts` — `assembleFinding`: evidence assembly (code locations + issue body + related matches), confidence = clarity + evidence-count + code-location terms (capped 0..1), gate at 0.55; every FindingRecord carries `duplicate_status` trail, `analysis_model/version` stamps, and weak-evidence hypothesis labels; exact/likely duplicates rejected with reasons; below-gate rejected with the numbers in the reason.
- `packages/discovery/src/prompts.ts` — `UNTRUSTED_CONTENT_RULE` (contract §50) in every system prompt; explicit "never claim uniqueness"; structured finding schema (additionalProperties: false); `buildAnalysisPrompt` wraps repo content in BEGIN/END UNTRUSTED CONTENT markers; `parseAnalysisFinding` strips fences and validates shape.
- `packages/discovery/src/reference.ts` — reference mode with explicit reasons only (same_language / similar_title / shared_labels / same_topic); relevance floor 0.3; no-reason references filtered out entirely.
- `packages/discovery/src/radar.ts` — project radar: project-scoped candidate items (stale → attention), TODO/FIXME scanner with file:line, `fetchAdvisories` via the repo-scoped dependabot alerts endpoint with source links (state=open only). Caught myself mid-implementation: I first wrote `/advisories` (global, unscoped — would have produced false "advisories for your repo") and fixed it to `/repos/{repo}/dependabot/alerts`.
- 14 new tests (28 discovery total).
