# 2026-09-24 (session 13) — CI fix: approval execution + git identity + secret-scanner-safe fixtures

## Root cause (CI runs 36315360747 / 36316170739, both red)

The gate's approved-commit tests failed on CI but passed locally for ONE reason: the scratch repo had no local git identity. Setup commits used per-command '-c user.name/-c user.email' flags, but the gate-executed 'git commit' runs WITHOUT flags - on the identity-less CI runner it exits 128 ('Please tell me who you are') -> out.ok false. Windows passed only because this machine has a global identity. The approval flow itself was correct; the fixture was environment-incomplete.

## Fix (implementation level, no assertion weakening)

1. gate.test.ts beforeEach now sets LOCAL identity ('git config user.name/user.email') in the scratch repo after init - cross-platform, self-contained.
2. Assertion diagnostics upgraded: expect(ok, `refusalReason: ... | stderr: ...`) per the task's Priority 4.
3. Security UPGRADES from the task review (beyond the fix):
   - verifyGrantedApproval now binds the EXECUTION CONTEXT: actor, session, task, policy_version must match the approval record (contract s58 binds them; execution now verifies). Wrong actor / policy-drift tests added and refused with 'context_mismatch'.
   - Approval state machine made explicit: status enum += 'consumed'. The gate consumes the approval on ANY terminal outcome (executed, failed, or drift-to-deny). verifyGrantedApproval rejects 'consumed' with a distinct reason. Replay protection is now STATE-based (durable) with the in-memory set as a second layer for granted-copy replays.
   - Failed-execution policy: a failed approved command ALSO consumes the approval - retries require fresh approval (safe default; tested).
4. Secret-scanner-safe fixtures: all format-valid fake tokens in redaction/broker tests are built from fragment joins - no contiguous ghp_/sk-ant-/AKIA/AIza/JWT literals ship in source (fixes the GitHub secret-scanning alert on the dummy Google key).
