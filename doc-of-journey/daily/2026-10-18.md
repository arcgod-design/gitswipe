# 2026-10-18 — the workstation setup: phone paired through the tunnel (branch: dev)

## What happened

The user asked for the Cloudflare tunnel + the workstation setup on the phone. The phone and laptop were on different subnets (10.121.x vs 10.52.x) so the direct connection was impossible — exactly the scenario the tunnel solves.

## The setup (all through adb, no manual phone interaction)

1. cloudflared downloaded (51.8 MB) + a fresh tunnel started: `https://brunette-conducted-principle-bailey.trycloudflare.com`
2. A fresh pairing code issued, the app data cleared, the URL + code typed via adb input, Pair tapped
3. First attempt: "pairing code expired" (the 10-min TTL ran out during the UI automation — codes are single-use + time-limited by design)
4. Second attempt: "Failed to fetch" (the tunnel had gone stale; the old cloudflared process wasn't proxying anymore)
5. Fresh serve restart + fresh tunnel + fresh code: **PAIRED SUCCESSFULLY**
6. The phone showed a real TypeScript issue from TanStack/query #11586, scored 0.80, "matches your strongest languages"

## The connection-failed fix

When the phone can't reach the workstation (network change, tunnel down, serve down), the app now shows a clear "Could not reach the workstation" state with the error detail + a "Re-pair with the workstation" button that clears the token and return to the pairing screen. Before: silent failure with just the tabbar.

## Lessons recorded

- Pairing codes expire in 10 minutes and are single-use — automate the FULL sequence (issue code + fill + tap) in one shot, don't split across commands
- Cloudflare quick tunnels go stale if the serve restarts under them — restart both together
- The CORS origins were already correct (capacitor://localhost was in the list from D3); the failure was the stale tunnel, not CORS
