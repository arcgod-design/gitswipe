# 2026-10-18 (session 2 of the day) — session recovery with uncommitted-work detection (branch: dev)

## What was built

whynot #8 upgraded from "honest FAIL only" to "honest FAIL + uncommitted-work detection": when the daemon restarts and a zombie session is recovered as FAILED, the recovery checks the worktree for uncommitted agent code. If found, the failure reason tells the user exactly where to find their agent's work: "N file(s) with uncommitted agent work in <path> — the code is preserved; review and commit manually or re-dispatch."

Also fixed: the FeedScreen's connection-failed state was using setPaired/setScreen directly (App-level state), which doesn't exist inside the FeedScreen component. Refactored to an onRePair callback prop passed from App — cleaner architecture (FeedScreen doesn't know about App's state internals).
