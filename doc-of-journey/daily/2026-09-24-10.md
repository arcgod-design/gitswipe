# 2026-09-24 (session 10) — WEEK-05: the daemon becomes real (branch: dev)

## What was built

`apps/daemon/src/workstation/` — the production service:
- `config.ts` (E1): zod-validated env config, documented precedence (defaults < env), loopback default 127.0.0.1:7420; `describeBind` exposes lan vs loopback.
- `identity.ts` (E2): durable ed25519 device identity (pkcs8 private key on disk mode 0600, spki public), self-verification on load, corruption (swapped key) is DETECTED not trusted.
- `pairing.ts` (E2): disk-backed pairing codes (single-use, TTL, expired sweep) + device registry (tokens stored as SHA-256 hashes only). Cross-process correct: `jarvisd pair` (CLI) and `serve` (daemon) share state through the data dir; verifyToken/revoke/list re-read disk so CLI revocation kills live tokens.
- `journal.ts` (E4): global-sequence event journal (gap-checked, monotonic across restarts), `emit` builds real protocol envelopes, `readFrom(cursor)` replay, `snapshot(sessionId)` for s121 reconnects.
- `queue.ts` (E6): durable JSONL task queue — enqueue/claim survive restarts.
- `health.ts` (E6): workstation health (git, disk via statfs, policy rules, agent availability, heartbeat timestamp).
- `server.ts` (E3+E5): production API — loopback default; origin lock (403 cross-origin); /healthz (open but reveals only protocol identity); POST /api/pair (code -> device token); Bearer device-token auth on everything else; GET /api/workstation (health + capabilities + handshake fields); GET /api/sessions?from=N (cursor fetch); GET /api/events SSE (global tail, stops on client close).
- CLI: `serve` is REAL now (replaces the honest placeholder); `pair` (issues code); `devices list|revoke`.

## Bugs the tests + live run caught (all real)

1. `privateKey.export({type:"spki"})` — invalid; export the PUBLIC key from the pair.
2. Pairing codes were in-memory per instance -> the CLI pair process and the daemon could never see each other's codes. Fixed: codes disk-backed. Same staleness class: verifyToken/revoke/list must re-read disk (a CLI revoke must kill a live server token).
3. /api/workstation returned the workstation identity's deviceId — clients could not learn their own paired-device id to revoke. Now returns workstationId + pairedDeviceId.
4. SSE test initially awaited events that were never emitted (reconnect cursor design flaw) — restructured to emit a second event before reconnecting.
